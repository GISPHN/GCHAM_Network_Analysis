# G-CHAM Network Analysis

QGIS 3系・4系に対応した、道路ネットワークを使う経路・到達圏解析と保健師チーム巡回計画のプラグインです。

## 主な機能

- 道路網に沿った最短距離ルートと参考所要時間の算出
- 距離または所要時間による到達圏解析（起点ごと、全起点の統合）
- 複数チームによる訪問先巡回計画
- 未訪問先がある場合の、チーム数・行動可能時間・共通対応時間の自動調整
- 歩行、自転車、自動車統計、任意速度の選択
- CSV、Excelサマリー、GeoPackageへの出力
- 日本語・英語の画面表示と出力

到達圏の区間明細はCSVとGeoPackageに保存し、QGISには集約した表示用レイヤを追加します。大規模な統合ラインは初回描画の負荷を抑えるため、非表示で追加されます。

## インストール

QGISの「プラグイン」→「プラグインの管理とインストール」→「ZIPからインストール」から、配布ZIPを指定してください。

## 入力データと注意点

道路ネットワークは、交差点で分割・接続されたメートル単位の投影座標系のラインレイヤを使用してください。起点・目的地にはポイントレイヤを使用します。

このプラグインは入力された道路形状と選択速度を用いた参考解析です。一方通行、車両や歩行者の通行規制、交差点待ち、時間帯による速度変化などを完全には再現しません。巡回計画は試作ヒューリスティックによる計画であり、全体最適を保証しません。結果を実務に使う場合は、入力データ、設定、未訪問先、経路を確認してください。

詳しい操作手順、速度の出典、結果の解釈、制約事項は[日本語ガイド](README_ja.txt)をご覧ください。

## 解析手法

以下はバージョン0.4.13の実装に基づく説明です。後続バージョンでは、解析方法や出力項目が変わる可能性があります。

### 道路グラフの作成

道路ラインの連続する頂点をノード、隣り合う頂点間の線分をエッジとするグラフ (G=(V,E)) を作ります。ノード座標は0.1 mの許容幅で同一ノードにまとめ、各エッジの長さは投影座標上の平面距離で計算します。各エッジは両方向に登録されます。

起点・目的地は最近傍の道路ノードに接続します。したがって、点から道路ノードまでの直線距離も経路距離に加算されます。道路の交差がラインの頂点として接続されていない場所は、グラフ上でも接続されません。道路の方向規制や移動手段ごとの通行可否は判定しません。

### 最短距離ルート

エッジ長を重みとしてDijkstra法を適用し、グラフ上の最短距離を求めます。目的地を根として探索し、複数起点への距離・経路を同じ探索で求めます。Dijkstra法は、非負のエッジ重みを持つグラフ上で最短経路を求める標準的なアルゴリズムです（Dijkstra, 1959）。

経路の参考所要時間は、得られた距離を選択速度 (v) で割って算出します。

`参考所要時間 = 経路距離 / 選択速度`

このため、現在の最短経路モードは「最短距離ルート」であり、「最短時間ルート」ではありません。道路ごとの速度差や混雑を考慮した時間最小化は行っていません。

最短経路モードでは、起点・目的地の周辺から道路グラフを構築します。候補経路のコストと、解析矩形の外側を通る場合に必要となる距離の下限を比較し、範囲外により短い経路がないと判断できるまで範囲を段階的に広げます。道路ネットワーク全域が範囲に入った場合は全域を使います。この局所化は計算量を減らすための実装上の処理であり、別の最短経路理論ではありません。

### 到達圏

到達圏は、起点ノードからDijkstra法で累積コストを広げ、指定した上限以内のノードと道路区間を抽出します。距離基準ではエッジ長を、時間基準ではエッジ長を選択速度で割った値をコストにします。時間基準は道路網全体に同じ速度を適用する静的な計算です。

道路区間の途中までしか上限内に入らない場合は、残りコストに対応する区間部分を出力します。複数起点の統合モードは多起点Dijkstra法に相当し、各地点・区間に対して最小コストで到達する起点を割り当て、いずれかの起点から届く道路範囲を重複なく出力します。統合結果の起点別内訳は最小コストによる帰属であり、各起点が単独で到達できる範囲を示すものではありません。起点別に比較する場合は個別モードを使用してください。

到達圏では、上限距離または上限時間とスナップ許容距離から探索対象範囲を設定して道路グラフを構築します。凸包ポリゴンは道路到達範囲の外縁を要約する図形であり、ポリゴン内部すべての地点が道路網上で到達可能であることを示しません。

### 複数チームの巡回計画

拠点と各訪問先の組み合わせについて、道路グラフ上の最短距離を計算し、選択速度で移動時間に換算します。巡回計画は、単一拠点から複数チームが出発する、勤務時間・訪問先対応時間の制約を持つ車両経路問題（VRP）に類似した設定です。VRPは拠点から複数の訪問先へ車両を割り当てて経路を決める組合せ最適化問題として研究されてきました（Dantzig and Ramser, 1959）。

ただし、プラグインは厳密解法ではなく、次の構成的ヒューリスティックを使います。

- 全訪問先を回るモードでは、対応時間が長い訪問先や拠点から遠い訪問先を先に検討します。勤務時間内に入るチーム・巡回順への挿入候補を評価し、追加所要時間とチーム間の作業時間バランスを使って割り当てます。
- 時間内に対応量を最大化するモードでは、訪問先の報酬を追加作業時間で割った値を基準に、勤務時間内に入る訪問先を貪欲に選択します。報酬は設定に応じて対応人数、または対応人数と優先度の積です。訪問先の一部だけに対応する部分対応は扱いません。
- 初期の巡回順を作った後、2-opt法で経路の一部を反転し、移動時間が短くなる変更を試します。2-optは巡回路の辺交換による局所改善法です（Croes, 1958）。実装では改善パス数に上限を設けています。

訪問先の挿入順や局所改善に依存するため、巡回計画は全体最適を保証しません。全訪問先モードで未訪問先が残っても、数学的に「実行不可能」と証明したことにはなりません。出力されたチーム別の訪問順、勤務時間、未訪問先を確認してください。

未訪問先がある場合の自動調整は、設定された優先順位に沿ってチーム数、行動可能時間、共通対応時間を候補値で再計算します。実装は離散的な候補値を二分探索で試す方式です。巡回計画自体がヒューリスティックであるため、調整後に全訪問できた場合は設定条件下で実行可能な計画が得られたことを示しますが、必要最小限の変更や最適性を保証しません。未訪問が残った場合も、全パラメーターの組み合わせを網羅した不可能性の証明ではありません。

### 研究で利用する際の報告事項

再現性と解釈のため、少なくとも次の情報を方法に記載してください。

- プラグイン名、バージョン、QGISのバージョン
- 道路データの出典・版、座標参照系、道路グラフの作成方法
- 起点・目的地の定義、選択地物の条件、スナップ許容距離
- 距離基準か時間基準か、速度値・単位・根拠と適用範囲
- 到達圏の上限、起点ごとの個別解析か全起点統合か
- 巡回計画では、拠点、チーム数・人数、行動可能時間、休憩、対応時間、報酬の定義、帰着条件
- 未訪問先の有無、自動調整の設定と調整後の値

可能であれば、小規模な既知ネットワークで経路距離・到達区間を手計算や独立した実装と照合し、巡回計画は複数の条件や初期設定で結果の安定性を確認してください。道路グラフの構造、入力データの位置精度、速度仮定、ヒューリスティックによる近似は、研究結果の限界として扱う必要があります。
